\subsection{Status reporting}\label{sec:5.2}
\begin{itemize}
\item The PM issues a weekly delivery report to the project team, IT, HR/\allowbreak{}L\&D and relevant work-package owners, and a monthly written summary to CHRO/\allowbreak{}CFO, Compliance and department managers. Urgent approval requests, critical incidents and forecast gate misses are communicated when identified. Routine monthly reporting does not delay escalation.
% Source GP4 Skeleton block 203
\item \textbf{Report distribution and evidence:} Teams/\allowbreak{}Jira for live actions and issues, email for stakeholder summaries and decisions, approved records retained in the shared OneDrive project repository.
% Source GP4 Skeleton block 204
\item Report milestone variance against both the original December 31 target and the January 6 working forecast, intermediate gate dates, pooled resource demand versus confirmed capacity, contingency committed/\allowbreak{}remaining, SLA breaches, test results, defects, and outstanding approvals.
\end{itemize}

\subsection{Project documentation}\label{sec:5.4}
The Project Manager maintains controlled copies of the plan, WBS, dictionary, schedule, risk register, decision log, change log, meeting records, test evidence and acceptance records in the shared project repository. Editable WBS and schedule sources are linked in Sections 2.2 and 3.8. Jira holds work items, defects and action tracking. Section 6.1 defines documentation naming, version and access standards.


% Source GP4 Skeleton block 216
Approved baseline copies retain their version, approval date and approver. The PM retains superseded versions and distributes the current approved references after changes are authorized under Section 1.11. Vendor access is limited to approved technical records and does not confer LMS permissions.


% Source GP4 Skeleton block 217
The Gantt overview and the six numbered detail panels are maintained as separate views and exports. The full schedule overview remains separate from the detail-panel PDF. Final report tables and figures use the same deliverable names and work-package IDs as Section 1.2 and the WBS dictionary.
